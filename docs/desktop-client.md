# Настольный клиент

Реализованы регистрация, вход, профиль, обновление профиля, выход, комнаты и сетевая тренировочная арена. Враги и бой пока не реализованы. Проверка двух игроков описана в [инструкции для комнат и арены](rooms-and-arena.md).

## Запуск на этом компьютере

Java 21, PostgreSQL и библиотеки клиента уже подготовлены. Открой два окна PowerShell. Все команды ниже выполняются из `C:\Users\Mikey\Desktop\gamedead`.

В первом окне запусти сервер на порту 8081:

```powershell
cd C:\Users\Mikey\Desktop\gamedead
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-21.0.12.1'
$env:GAMEDEAD_PORT = '8081'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-server.ps1
```

Введи пароль PostgreSQL в скрытом запросе. Дождись сообщения `Started GameDeadServerApplication`. Оставь это окно открытым. После обновления кода останови старый сервер через Ctrl+C и запусти заново.

Во втором окне запусти клиент:

```powershell
cd C:\Users\Mikey\Desktop\gamedead
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-client.ps1 -ServerUrl http://127.0.0.1:8081
```

Откроется отдельное игровое окно. Создай аккаунт, затем войди под созданным логином. Игровой пароль выбирай самостоятельно: он не связан с паролем PostgreSQL. При входе загружается сохранённый профиль; опыт нового аккаунта равен нулю.

Порт сервера и адрес в клиенте должны совпадать. По умолчанию оба используют 8080; для этого не задавай `GAMEDEAD_PORT`, а у клиента опусти `-ServerUrl`.

## Сборка и запуск без IntelliJ IDEA

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-21.0.12.1'
$env:GRADLE_USER_HOME = Join-Path (Get-Location) '.gradle-user-home'
.\gradlew.bat build :client:installDist --offline --console=plain
```

Обычная сборка не открывает окно и не обращается к PostgreSQL. Серверные интеграционные тесты запускаются отдельно, как описано в `local-development.md`.

Готовый комплект: `client\build\install\client`. Он содержит клиент, протокол, `game-core`, графику, шрифт и библиотеки. Запуск:

```powershell
.\client\build\install\client\bin\client.bat --server-url=http://127.0.0.1:8081
```

Переносить нужно всю папку `client`, а не один `.bat` или `.jar`. На другом компьютере для запуска требуется Java 21. Сервер там не запускается автоматически. Для игры через интернет позже понадобятся размещённый сервер и HTTPS: сейчас сервер по умолчанию принимает подключения только с этого компьютера.

На новом рабочем месте библиотеки и шрифт загружаются командой:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\prepare-client.ps1
```

Скрипт подготовки загружает библиотеки из Maven Central и Noto Sans с лицензией OFL из официального репозитория Google Fonts. В остальных скриптах клиента загрузок нет.

## Что проверить вручную

1. Создание аккаунта, занятый логин, несовпадающие пароли.
2. Вход под своим аккаунтом, имя и опыт в профиле, обновление и выход.
3. Tab между полями, Enter для отправки формы, переключение видимости пароля.
4. Вставку своего Unicode-пароля с пробелами; клиент не обрезает и не нормализует пароль.
5. Окно 1280×720 и 960×640. Если ошибок много, правая панель прокручивается колёсиком.
6. Вход при выключенном сервере: появится сообщение об ошибке, окно продолжит работать.
7. Два разных аккаунта в одной комнате: состав, готовность, запуск, движение WASD и рывок на Shift. Оба клиента должны видеть движения друг друга.

## Устройство клиента

| Часть | Назначение |
| --- | --- |
| `desktop/DesktopLauncher` | Создание окна, адрес сервера из `--server-url` |
| `ui/GameDeadClient`, `UiTheme` | Scene2D, формы, русский шрифт, процедурный декор |
| `auth/AuthController`, `AuthState` | Переходы экранов, локальная валидация, сессия в памяти |
| `net/HttpGameApi` | Асинхронный JSON API, Bearer, таймауты и понятные ошибки |
| `net/LimitedBodySubscriber` | Ограничение ответа до 64 KiB |
| `room/RoomController`, `RoomState` | Состояние комнаты, переподключение и защита от запоздавших событий |
| `net/SocketRoomChannel`, `RoomMessages` | WebSocket, проверка сообщений и ограничение очереди ввода |
| `ui/RoomScreen`, `ArenaRenderer` | Лобби, арена, анимация и сглаживание координат |
| `protocol` | Общие DTO клиента и сервера |
| `game-core` | Общая карта; расчёт движения выполняется на сервере |

Spring, Hibernate и драйвер PostgreSQL в клиент не входят. Секреты не записываются в настройки; закрытие окна удаляет локальную сессию. Кнопка выхода дополнительно отзывает её на сервере. Если сервер недоступен, выход на компьютере завершается с сообщением, что серверная сессия истечёт автоматически.

Сетевые операции выполняются вне графического потока. Завершения обрабатываются через `Gdx.app.postRunnable`; номер операции защищает от запоздавших ответов. Подключение ограничено 5 секундами, весь запрос с телом ответа — 10 секундами. Перенаправления отключены.

## Проверки

```powershell
.\gradlew.bat :client:test --offline --console=plain
.\gradlew.bat :client:desktopCheck --offline --console=plain
```

Первая команда проверяет сетевые запросы на локальном тестовом HTTP-сервере, переходы состояния и сообщения WebSocket; отдельная БД не нужна. Вторая явно запускает скрытые окна OpenGL, проверяет формы, комнаты и арену при двух размерах, сохраняет снимки в `client/build/reports/desktop` и закрывает окна. Она использует тестовые данные без обращения к рабочему серверу. Нужна доступная графическая среда; эта проверка не включена в обычный `build`.

Шрифт: Noto Sans, SIL Open Font License; лицензия поставляется рядом с ним в `src/main/resources/fonts/OFL.txt`. Панели и руны рисуются кодом libGDX.

Арена и маг: DungeonTileset II v1.7, автор 0x72, CC0. Атлас и список кадров взяты из пользовательской папки `visual` без изменений; источник указан в `client/src/main/resources/game/0x72/SOURCE.txt`.

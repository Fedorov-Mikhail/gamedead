# «Печать сумрака»: настольный клиент аккаунтов

Статус: согласовано пользователем; реализовано в модуле `client`. Запуск и проверки описаны в `docs/desktop-client.md`.

## Цель

Дать игроку обычное настольное приложение: создать аккаунт, войти, увидеть свой профиль и выйти без команд PowerShell для работы с API. Клиент использует уже реализованный Spring Boot сервер и существующие DTO. Пароль PostgreSQL клиенту не требуется.

Сохраняются требования к будущей игре: фэнтезийная арена, 2–4 игрока, около 30 минут на забег, рывок на Shift. Сетевые комнаты и игровой мир — отдельный следующий этап после проверки клиента аккаунтов.

## Границы этапа

Результат — запускаемое приложение libGDX для Windows x64 с русскими экранами входа, регистрации и профиля, подключённое к реальному API. Сервер и клиент запускаются отдельными процессами. Запуск сервера и БД не прячется в клиент.

Не требуется менять схему БД или HTTP-контракт сервера. Новые серверные маршруты не добавляются. Существующие тесты серверного этапа сохраняются.

## Архитектурный выбор

Выбран один модуль `client` в существующем Gradle-проекте. Он содержит desktop launcher, libGDX приложение, экраны и отдельные обычные Java-классы для HTTP и состояния авторизации. Это соответствует текущей единственной платформе — компьютеру.

Альтернатива — сразу разделить клиента на `client-core` и `client-desktop`. Такой вариант полезен при добавлении Android или браузера, но сейчас добавил бы конфигурацию без необходимого результата. Отдельный Spring-контекст в клиенте также не требуется.

Зависимости: `client → protocol`; зависимости на `server` и JPA отсутствуют. `game-core` появится вместе с игровой симуляцией.

## Экранный сценарий

1. Приложение открывает экран входа. Поля: «Логин», «Пароль»; кнопки «Войти» и «Создать аккаунт». Пароль маскируется, рядом переключатель видимости.
2. Регистрация содержит логин, отображаемое имя, пароль и подтверждение пароля. Назад возвращает к входу. Проверка совпадения паролей выполняется локально, правила учётных данных и уникальности окончательно определяет сервер.
3. Успешная регистрация возвращает к входу с заполненным логином и сообщением «Аккаунт создан. Теперь можно войти». Пароли очищаются; автоматического входа нет, как предусмотрено серверным контрактом.
4. После входа клиент получает `/me`. Только успешный ответ профиля открывает главное меню.
5. Главное меню показывает отображаемое имя, логин и постоянный опыт аккаунта, содержит действия «Обновить профиль», «Выйти из аккаунта» и «Закрыть игру». Неактивных кнопок будущих игровых функций нет.
6. Выход очищает локальную сессию и отзывает её на сервере. Если сервер недоступен, локальный выход всё равно завершается; пользователь получает понятное сообщение о том, что подтвердить выход на сервере не удалось.

Во время запросов кнопка отправки и редактирование соответствующей формы блокируются, отображается короткое состояние загрузки. Окно продолжает перерисовываться и реагировать на перемещение/закрытие.

## Внешний вид

Окно 1280×720, изменяемый размер, минимум 960×640. Полноэкранный режим, музыка и сложные анимации не входят в этот этап.

Тёмный фэнтезийный интерфейс: почти чёрный сине-серый фон, каменные панели, приглушённые золотые рамки, фиолетовое свечение рун. Заголовок «Печать сумрака» слева, форма в панели справа. На меньшем размере элементы остаются доступны без обрезки. Ошибки выделяются цветом и сопровождаются текстом.

Первые панели, кнопки и рунический декор рисуются средствами libGDX: единая палитра и простые текстуры, без загрузки случайных картинок разных стилей. Окружение и персонажи из согласованного набора 0x72 подключаются на этапе арены. Настоящие иллюстрации или генерация изображений сейчас не требуются.

UI — Scene2D UI со своим Skin, Table и масштабируемым viewport. Ресурсы шрифта, текстур и Stage освобождаются при закрытии. Переключение экранов освобождает старые обработчики ввода и не создаёт второй комплект общих ресурсов.

## Шрифт и Unicode

Для текста нужен Noto Sans с кириллицей из официального проекта Google Fonts вместе с OFL.txt. libGDX FreeType создаёт необходимые размеры шрифта при запуске. Шрифт поставляется в ресурсах приложения: наличие конкретного системного шрифта на другом компьютере не требуется.

Латиница, русский алфавит с Ё/ё, цифры и знаки интерфейса должны отображаться корректно. Непокрытые шрифтом символы могут отображаться заменяющим знаком, но клиент не должен молча удалять их из введённых строк. Ввод и вставка пароля передаются без trim и нормализации; маскирование не меняет содержимое. Проверяется вставка Unicode-пароля, в том числе кириллицы и emoji. Цветовая разметка в пользовательском имени отключена.

## Сеть и состояние

Используется Java 21 HttpClient, асинхронные запросы и JSON через уже используемый в проекте Jackson 3.1.5. Redirect policy — NEVER: токен не передаётся автоматически на другой адрес.

Настраиваемый базовый адрес сервера, по умолчанию `http://127.0.0.1:8080`. При запуске можно передать `--server-url=http://127.0.0.1:8081`, если сервер запускается с `GAMEDEAD_PORT=8081`. Адрес проверяется до запроса: только HTTP/HTTPS URI без userinfo, query и fragment; для внешнего развёртывания применяется HTTPS по ранее согласованной архитектуре.

Все маршруты строятся как `/api/v1/...` относительно выбранного сервера. Тела запросов явно кодируются UTF-8, время сессии читается как Instant. Пароли, Authorization и токены не печатаются в логах и не записываются в файлы. Токен и профиль хранятся только в памяти. Клиент не содержит параметров PostgreSQL.

Таймаут установления соединения — 5 секунд, запроса — 10 секунд. Размер принимаемого JSON ограничивается 64 KiB. Неожиданный HTTP/JSON или недоступный сервер преобразуются в понятную ошибку без технического стека на экране.

401 при входе показывает ошибку учётных данных. 401 при запросе профиля сбрасывает сессию и возвращает ко входу. 400 показывает связанные с полями ошибки, 409 — занятый логин, 429 — необходимость подождать с учётом Retry-After. Неизвестные поля ошибки игнорируются; неподходящий ответ сервера не вызывает падение окна.

Состояние авторизации и завершение запросов отделены от экранов. Изменение Scene2D выполняется только в графическом потоке через `Gdx.app.postRunnable`. У операции есть номер поколения: ответ завершённой старой операции не открывает меню после выхода или перехода на другой экран. Повторный клик не создаёт второй запрос. При закрытии окна незавершённые операции отменяются, HTTP executor закрывается.

## Версии и загрузки

- Java 21 и Gradle Wrapper 9.8.1 сохраняются.
- libGDX 1.14.2: `gdx`, `gdx-backend-lwjgl3`, `gdx-platform` с desktop natives, `gdx-freetype` и его desktop natives.
- LWJGL и его совместимые библиотеки определяются выбранным backend; необходимые native-компоненты включаются в desktop distribution.
- Jackson 3.1.5 подключается к клиенту напрямую, без BOM Spring Boot и без серверных библиотек.
- JUnit Jupiter 6.0.3 для Java-классов клиента; сетевые тесты используют локальный JDK HttpServer и не требуют PostgreSQL.

Библиотеки libGDX/LWJGL и шрифт загружены пользователем через `scripts/prepare-client.ps1`. Агент не запускает загрузки. Команда `:client:run` запускает окно; `scripts/start-client.ps1` помогает выбрать адрес сервера и использует автономный режим Gradle.

## Проверка

- Обычные тесты HTTP-клиента проверяют реальные UTF-8 тела, Bearer только после входа, ответы 400/401/409/429/500, отсутствие сервера, таймаут, повреждённый и слишком большой JSON и запрет перенаправления токена.
- Тесты состояния проверяют регистрацию без автоматического входа, загрузку профиля до показа меню, выход при недоступном сервере, двойное нажатие, устаревшие результаты и закрытие клиента во время запроса.
- Сборка `build` не запускает окно и не требует работающего сервера/БД. Дополнительный запуск `:client:run` открывает настоящее окно; `:client:installDist` создаёт запускной комплект с библиотеками.
- Ручная проверка настоящего окна: русский текст, ввод/вставка пароля, Tab/Enter, видимость пароля, размеры 960×640 и 1280×720, регистрация/вход/профиль/выход на существующем сервере, поведение при выключенном сервере.
- Графический запуск нельзя объявлять проверенным по одним Java-тестам. Если инструментам недоступно управление настольным окном, визуальную проверку выполняет пользователь по точному сценарию.
- Существующие серверные тесты остаются независимыми от графических библиотек. Серверные интеграционные тесты по-прежнему используют только отдельную тестовую БД.

## Критерий готовности

Пользователь запускает сервер и отдельный клиент, создаёт аккаунт через окно, входит, видит собственный сохранённый профиль и выходит. Ошибки сети не замораживают приложение. Клиент запускается из Gradle и из собранной desktop distribution; инструкции не требуют вручную выбирать main class в IDEA.

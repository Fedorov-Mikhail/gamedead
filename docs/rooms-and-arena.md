# Комнаты и тренировочная арена

Реализована совместная тренировка для 2–4 игроков: комнаты по коду, готовность, общий мир, движение WASD, столкновения со стенами и рывок на Shift. Врагов, атаки, опыта и таймера забега пока нет. Цель полноценного забега остаётся прежней — около 30 минут.

## Запуск двух игроков

Дополнительно скачивать ничего не нужно. Используется существующая PostgreSQL; новые SQL-команды и миграции для этого этапа не требуются. Аккаунты сохраняются в БД, комнаты и арена существуют в памяти сервера.

Закрой старые окна клиента. В окне старого сервера нажми Ctrl+C. Из папки проекта запусти обновлённый сервер:

```powershell
cd C:\Users\Mikey\Desktop\gamedead
$env:GAMEDEAD_PORT = '8081'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-server.ps1
```

Введи пароль PostgreSQL в скрытом запросе и дождись сообщения `Started GameDeadServerApplication`.

Открой ещё два окна PowerShell. В каждом выполни:

```powershell
cd C:\Users\Mikey\Desktop\gamedead
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-client.ps1 -ServerUrl http://127.0.0.1:8081
```

Первый запуск может собирать изменённый код. Скрипты клиента работают без загрузок. Для последующих запусков можно использовать также собранный комплект `client\build\install\client\bin\client.bat` с аргументом `--server-url=http://127.0.0.1:8081`.

1. Войди в двух окнах под **разными аккаунтами**. Второе игровое подключение под тем же аккаунтом заменяет первое.
2. В профиле каждого игрока нажми **«Играть с друзьями»**.
3. Первый игрок создаёт комнату и сообщает код второму. Второй вводит код и присоединяется.
4. Все нажимают **«Готов»**. Владелец начинает тренировку; минимум — два подключённых и готовых игрока.
5. Переключайся между окнами: **WASD** перемещает мага, **Shift во время движения** делает рывок. Восстановление рывка — две секунды. Пройти сквозь стены нельзя.
6. Владелец может вернуть всех в лобби. Каждый может выйти из комнаты; при уходе владельца права переходят оставшемуся участнику.

Имена и цветные отметки помогают различать одинаковых магов. Во время игры состав комнаты закрыт для новых участников.

При обрыве соединения место сохраняется на 30 секунд. Нажми «Подключиться», чтобы вернуться. После этого срока игрок удаляется из комнаты. Перезапуск сервера удаляет комнаты целиком; аккаунты остаются в PostgreSQL.

Сейчас сервер по умолчанию доступен только на этом компьютере. Подключение друзей через интернет потребует отдельного размещения и HTTPS/WSS — это следующий сетевой этап.

## Устройство

| Модуль | Что реализовано |
| --- | --- |
| `game-core` | Карта 40×24 клетки по 16 пикселей, фиксированный шаг мира, движение, столкновения, рывок |
| `protocol` | Состояние комнаты, события WebSocket, команды ввода и снимки мира |
| `server` | Комнаты, проверка прав и готовности, расчёт мира, рассылка и проверка сессий |
| `client` | Экраны, асинхронная сеть, управление, анимация и сглаживание координат |

Сервер рассчитывает мир 20 раз в секунду и отправляет снимки 10 раз в секунду. Клиент передаёт только направление и нажатие Shift; координаты определяет сервер. Номер команды защищает от устаревшего ввода, а ввод без обновления отключается через 300 мс. Предсказание собственного движения пока не используется.

Операции комнаты проходят через авторизованный HTTP API:

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/v1/rooms/me` | Текущее членство |
| POST | `/api/v1/rooms/create` | Создание комнаты |
| POST | `/api/v1/rooms/join` | Вход, тело `{"code":"ABC234"}` |
| POST | `/api/v1/rooms/ready` | Готовность, тело `{"ready":true}` |
| POST | `/api/v1/rooms/start` | Начало тренировки владельцем |
| POST | `/api/v1/rooms/stop` | Возврат всех в лобби владельцем |
| POST | `/api/v1/rooms/leave` | Выход участника |

Постоянное соединение `/ws/game` использует Bearer в заголовке подключения. Сначала клиент открывает его, затем выполняет операции комнаты. Сервер получает личность из сессии, а имя — из профиля. Игровые сообщения имеют версию протокола 1. Токен не передаётся в URL.

Одно соединение принимает до 60 команд в секунду; команда ограничена 2 KiB. Почтовый ящик участника хранит только последнее событие комнаты и последний снимок мира. Медленный клиент не накапливает очередь снимков. Действительность сессии проверяется отдельно от игрового расчёта каждые пять секунд; отзыв или истечение закрывает соединение.

Для прототипа установлены пределы 64 комнаты и 512 активных игровых соединений на процесс. Это ограничения ресурсов, а не результаты нагрузочного тестирования.

## Графика

Использован DungeonTileset II v1.7 из `visual`: каменный пол, стены, колонны и маг `wizzard_m`. Отрисовка использует исходный атлас, анимации ожидания и бега, фильтрацию без размытия. Источник и сведения о CC0 включены в комплект рядом с атласом. Папка `visual` с исходными загрузками остаётся без изменений; служебные файлы macOS в клиент не копируются.

## Проверки

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-21.0.12.1'
$env:GRADLE_USER_HOME = Join-Path (Get-Location) '.gradle-user-home'
.\gradlew.bat build :client:installDist --offline --console=plain
.\gradlew.bat :client:desktopCheck --offline --console=plain
```

На этом этапе проходят 102 автоматических теста: 7 расчёта мира, 48 сервера и 47 клиента. Проверены реальные HTTP/WebSocket-подключения к изолированному Spring-серверу, две сессии, запуск, движение, возврат в лобби, отклонение некорректных команд и отзыв действующей сессии. Тесты не подключаются к рабочей PostgreSQL; её интеграционные проверки запускаются отдельно.

Графическая проверка проходит при размерах 1280×720 и 960×640: формы аккаунтов, комнаты, анимация, движение и рывок. Снимки находятся в `client/build/reports/desktop`. Следующая ручная проверка — два полных клиента с настоящими аккаунтами по инструкции выше.
